# План калибровки ASR (Whisper) — от измерения до слияния моделей

Этот документ — рабочий план для агента-исполнителя. Он самодостаточен:
не полагайся на память прошлых сессий, все нужные факты и пути собраны здесь.
Выполняй этапы по порядку; внутри этапа задачи тоже упорядочены. У каждого
эксперимента есть критерий принятия и **ветка Б** — что делать, если
эксперимент провалился. Провал эксперимента — это тоже результат: он
фиксируется в projectmem (`record_attempt` с outcome=failed) и закрывает
направление, чтобы никто его не переоткрывал.

---

## 0. Контекст, который обязан знать исполнитель

**Цель.** Найти наилучшую конфигурацию распознавания русской речи с
англицизмами для live-пайплайна Soma. Базовая модель — Whisper large-v3
(mlx). Вторая архитектура — GigaAM v2 (RNNT + CTC), русский без
латиницы/пунктуации, в 36 раз быстрее реального времени.

**Инструменты (все уже существуют):**

| Что | Где |
| --- | --- |
| Прогон моделей по корпусу | `Scripts/ground_truth_worker.py` (`--configs`, `--list`, `--best-of`) |
| Скоринг и сравнение с базой | `Scripts/asr_eval.py` (`--decodes`, `--baseline`, `--save`) |
| Замороженная база | `Scripts/asr_baseline.json` |
| Тесты harness | `tests/test_asr_eval.py` |
| Корпус и данные | `~/Library/Application Support/Soma/GroundTruth/archives/pre-structure-v1/root/` — архивный legacy workspace: `decodes.jsonl`, `gold.jsonl`, `verdicts.jsonl`, `review_progress.jsonl`, `experiments/` |
| Окружения движков | venv-whisper (mlx), venv-fasterwhisper (CTranslate2, int8 CPU, **единственный с beam search**), venv-gigaam (две головы RNNT/CTC) |

**Метрики asr_eval (пять):** WER по золоту ↓ (медианный), spots% (попадание в
решённые человеком спорные места) ↑, drift (медианный WER против gigaam,
покрывает весь корпус) ↓, latin% ↑, punct% ↑. **Абсолютные числа — не истина**
(золото выбиралось из выдачи движков и льстит им); осмысленна только дельта
до/после изменения. База w-greedy (переморожена после issue #0088, `asr_eval.py
--save Scripts/asr_baseline.json`; несравнима с более старыми числами —
normalize(), формат baseline и агрегация WER/drift изменились): WER 0.0286 /
spots 50.4 / drift 0.0927 / latin 18.9 / punct 81.8.

**Жёсткие факты, которые нельзя «передоказывать»:**

- mlx_whisper **не умеет** beam search (`beam_size` → NotImplementedError).
  Разнообразие — только temperature / conditioning / initial_prompt / best_of.
- `temperature=0.0` и `condition_on_previous_text=False` уже измерены на 80
  реальных записях и **приняты как дефолт** — не перепроверять.
- Автопринятие большинства голосов **небезопасно**: на 128 человеческих
  решениях слушатель отверг топ-вариант в 55% случаев. Любая схема «побеждает
  большинство» без прослушивания закрыта.
- Золотой корпус **дословный**: филлеры в нём оставлены (17/21 решений «слово
  присутствует»). Любая «чистка» текста ухудшает WER по построению — чистка
  живёт в отдельном слое (этап 7), не в ASR.
- `.txt` рядом с WAV — выход live-пайплайна, **не эталон**.
- Стоимость полного прогона корпуса (293 мин аудио × RTF): gigaam ~8 мин,
  w-greedy ~37 мин, w-prompt/w-fallback ~30 мин, w-sample ~90 мин,
  fw-beam ~170 мин. Ночь вмещает ~6–8 прогонов w-greedy-класса или 2–3 fw-beam.

**Правила гигиены экспериментов (действуют на всех этапах):**

1. **Никогда не дописывать в основной `decodes.jsonl`.** Каждый эксперимент
   пишет в свой файл: `GroundTruth/experiments/decodes-<этап>-<имя>.jsonl`.
   Кэш не имеет провенанса (ключ только имя+конфиг, issue #0073) — смешение
   прогонов с разными параметрами под одним именем конфига отравит кэш молча.
2. Каждому экспериментальному конфигу — **уникальное имя** (`w-p-glos-v1`,
   а не переиспользованный `w-prompt`).
3. Каждый прогон скорится одной командой:
   `./asr_eval.py --decodes experiments/decodes-<имя>.jsonl --baseline Scripts/asr_baseline.json`.
4. Решение по эксперименту записывается в projectmem немедленно
   (`record_attempt`), принятая конфигурация — `add_decision`.
5. Изменил harness или normalize — **перемораживай базу** (`--save`) и явно
   отметь, что старые числа несравнимы с новыми.
6. Git: работа в ветках от main (никогда не в main напрямую), по ветке на этап.

## Этап 1. Укрепить измерительный прибор (обязательный пререквизит)

Пока прибор врёт, любой суточный прогон — шум. Этот этап дешёвый (без
прогонов моделей) и разблокирует всё остальное.

- [x] **1.1 Починить схлопывание символов в normalize()** (issue #0070 / #61):
  сейчас `C++ / C# / C → c`, т.е. ошибки на технических терминах невидимы
  для WER. Сделать normalize сохраняющим значимые символьные различия
  (минимально: `+`, `#` как часть слова). Прогнать `tests/` +
  `tests/test_asr_eval.py`.
  → Сделано в `Scripts/ground_truth_text.py` (`normalize`): `+`, `#`, `*`
  теперь выживают, если их пробег приклеен к букве/цифре хотя бы с одной
  стороны; одиночный символ (`5 + 3`) по-прежнему стрипается. Тест
  `test_normalize_keeps_c_plus_plus_and_c_sharp_apart_from_c` в
  `tests/test_ground_truth_consensus.py`. projectmem: fix issue #0070.
- [x] **1.2 Парная статистика в asr_eval.** Сейчас сравниваются средние — при
  94 золотых файлах дельта 0.002 неотличима от шума. Добавить в режим
  `--baseline` (при наличии пофайловых данных): счёт побед/поражений по
  файлам и sign-test или парный bootstrap p-value. Формат вердикта:
  «wins 31 / losses 9, p<0.01». Для drift (956 файлов) — то же самое,
  там мощность выше. Потребует сохранять пофайловые ошибки в `--save`
  (расширить формат baseline-файла, сохранив обратную совместимость чтения).
  → Сделано в `Scripts/asr_eval.py`: `score()` теперь также возвращает
  `wer_by_file`/`drift_by_file`; `--save` пишет их в baseline; `report()`
  печатает точный two-sided sign test (`sign_test_p`/`paired_verdict`,
  stdlib `math.comb`, без scipy) отдельно для WER и drift. Старый
  baseline без этих ключей просто не показывает строку вердикта —
  проверено на реальном `Scripts/asr_baseline.json` до переморозки.
  Тесты в `tests/test_asr_eval.py`.
- [x] **1.3 Параметризация воркера под эксперименты.** Проверено по коду:
  (а) воркер пишет декоды в stdout (`emit`), файла `--out` нет — прогоны
  перенаправляются `> experiments/decodes-<имя>.jsonl`, это нормально,
  но добавить `--out` стоит ради атомарности; (б) набор конфигов —
  захардкоженный словарь `CONFIGS`, т.е. промпты P2–P5 и сетки порогов
  этапов 2–3 сейчас непрогоняемы без правки кода → добавить
  `--config-file exp.json` (имя → dict опций mlx_whisper), не трогая
  встроенные семь конфигов; (в) у faster-whisper `beam_size=5` зашит в
  `faster_whisper_decoder` → вынести во флаг `--beam-size`.
  → Сделано в `Scripts/ground_truth_worker.py`: `--out PATH` пишет во
  временный `<PATH>.tmp` и переименовывает по завершении (stdout всё
  ещё получает каждую строку — тайлинг ночного прогона не сломан);
  `--config-file` подмешивает JSON `{имя: опции}` поверх `WHISPER_OPTIONS`
  аддитивно; `--beam-size` (default 5) заменил хардкод в
  `faster_whisper_decoder`. `ground_truth_runner.py` не передаёт новые
  флаги — старое поведение не тронуто.
- [x] **1.4 Переморозить базу** после 1.1–1.2: полный `asr_eval.py --save
  Scripts/asr_baseline.json` на текущем кэше. С этого момента все дельты
  считаются против новой базы.
  → Сделано: `Scripts/asr_baseline.json` переморожен, содержит
  `wer_by_file`/`drift_by_file` для всех 8 конфигов. Новые числа
  несравнимы со старыми (см. §0 выше).

- [x] **1.5 (добавлено после этапа 2) Устойчивость drift к выбросам**
  (issue #0086): не буквально пустой декод gigaam (тот уже отфильтрован —
  `normalize(row[REFERENCE]).split()` пуст), а **короткий** (1–2 слова):
  `wer()` не ограничен сверху, когда референс короткий, так что
  галлюцинирующий кандидат даёт WER>2.0 на одном файле; 3–4 таких файла из
  ~950 сдвигали среднее на +0.16 (видно на w-p-p3-v1). Порог по числу слов
  для исключения таких файлов — лишняя магическая константа; вместо этого
  агрегат drift переведён с среднего на **медиану** (`statistics.median`,
  stdlib, одна строка) — устойчива к любому числу выбросов, пока их <50%.
  → Сделано в `Scripts/asr_eval.py` (`score()`), регресс-тест
  `test_drift_uses_median_so_one_near_empty_gigaam_reference_cant_swing_it`
  в `tests/test_asr_eval.py`. Baseline переморожен: drift w-greedy
  0.1318→0.0927. Вердикты этапа 2 пересчитаны против нового baseline:
  `w-p-p3-v1` drift теперь **-0.0078 better** (p=0.00686), больше не
  аномалия — как и ожидалось, выводы этапа 2 не изменились, `w-p-p5-v1`
  остаётся принятым кандидатом. projectmem: fix issue #0086.

  **Довесок (issue #0088, найден при повторной самопроверке этого фикса):**
  та же необеспеченность сверху у `wer()` бьёт и по главной метрике WER
  (против золота), не только по drift — 6/98 золотых файлов 1–3 слова
  длиной, и mean WER был ~2× median почти у каждого конфига (w-greedy
  0.0621 mean / 0.0286 median). Решающие вердикты это не задевало — парный
  sign-test всегда был направленческим (win/loss по файлу, не по величине),
  так и остался байт-в-байт тем же (проверено пересчётом этапов 2 и 3.2:
  все `wins X / losses Y, p=...` не изменились) — задевало только сырое
  число `WER` в таблице/отчёте. Тот же фикс: `wer` тоже переведён на
  медиану, baseline переморожен повторно (WER w-greedy 0.0621→0.0286),
  регресс-тест `test_wer_uses_median_so_one_short_gold_reference_cant_swing_it`.
  projectmem: fix issue #0088.

**Критерий выхода:** тесты зелёные; baseline пересохранён; asr_eval печатает
парный вердикт. **Если 1.2 окажется сложным** (формат baseline мешает) —
ветка Б: минимум — счёт побед/поражений без p-value; это уже на порядок
информативнее среднего. Не застревать здесь дольше одного дня.

## Этап 2. Перебор initial_prompt (самая высокая ожидаемая отдача)

Гипотеза: промпт с реальными терминами проекта — «бесплатный глоссарий на
входе». Уже видно на w-prompt: latin 22.7% против 18.9% у w-greedy.

## Этап 3. Перебор параметров декодирования

Ручки, оставшиеся у mlx_whisper, плюс полный beam у faster-whisper.
Компьют не ограничен — ограничена только ночь, поэтому сетка растянется

## Этап 4. Комбинирование победителей + человеческое подтверждение (flip-review)

- [x] **4.1 Скомбинировать** лучший промпт × лучшие параметры декода в

  «промпт меняет пользу best_of»), трёхсторонним сравнением:

  | `w-greedy` (ни промпта, ни best_of) | 0.0286 | 50.4 | 18.9 | 81.8 |

  которую один greedy-проход с тем же промптом не раскрывает полностью.

  пункта («diff затопит пунктуацией») не реализовалось вообще, а не было
  отфильтровано постфактум. Категория `punct` в коде оставлена (корректна и
  протестирована отдельно на синтетике) на случай другого пайплайна

## Этап 7. Постобработка (набросок; НЕ начинать до завершения этапов 1–5)

```
Этап 6 — параллельно этапам 3–5, по остаточному принципу

```

(этапы 4.3, 5.3, при желании 6.1-экзамен уже решён). Никакого возврата к
очереди из 2000+ операций нет ни в одной ветке.
